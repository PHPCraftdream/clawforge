   аргументы пробелом в одну строку без кавычек, поэтому метасимволы скрипта доставались

4. `deploy` синкал `config/`/`recipes/` развёртывания без `--exclude` — `.env` внутри

5. `pull` не чистил обе копии share-архива, если `verifySnapshot` бросал исключение (а не
   просто возвращал `false`) — были только видны они в ветке проверки возврата.
6. Прямой `restore` (без `push`) стартовал gateway без preflight секретов, рискуя

## Decisions

- Регрессионные тесты пишутся так, чтобы их можно было ПОДТВЕРДИТЬ на баговом коде через
  `git stash` конкретного файла + прогон теста + `git stash pop` — тест, который никогда
  не был красным, ничего не доказывает. Использовано для всех 7 дефектов раунда 1.
- Первая версия теста на дефект 5 (pull cleanup) оказалась ложноположительной — считала
  вызовы `ctx.transport.remove()` вместо `exec("rm",...)`, из-за чего проходила и на
  старом баговом коде. Переписана на отслеживание правильного канала (exec) после того как
  git-stash-проверка это вскрыла.
- Суб-агенты запускаются строго в отдельных git worktree (правило CLAUDE.md), координатор
  ревьюит diff и мержит вручную — не доверяется автослиянию/пушу от самого агента.
- Для юнит-тестов раунда 2 выбрана стратегия "parallel sub-agents" (7 независимых файлов,
  без пересекающихся точек записи) вместо workflow/последовательных агентов — работа
  реально независима и выигрывает от wall-clock параллелизма.
