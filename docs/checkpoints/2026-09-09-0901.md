## Decisions

- Регрессионные тесты пишутся так, чтобы их можно было ПОДТВЕРДИТЬ на баговом коде через
  `git stash` конкретного файла + прогон + `git stash pop` — тест, который никогда не был
  красным, ничего не доказывает. Один раз это вскрыло ложноположительный тест (считал не
  тот канал — `transport.remove()` вместо `exec("rm",...)`), переписан.
- Суб-агенты — только в отдельных git worktree, координатор ревьюит diff и мержит
  вручную, не доверяясь автослиянию/пушу от самого агента (правило CLAUDE.md).
- Наивная реализация ротации снапшотов (sudo-проверка на каждый файл) заменена на batched
  версию (одна проверка эскалации + один комбинированный `rm -f` со всеми целями) — не
  просто стиль, а необходимость: на реальном 37-файловом бэклоге наивная версия вылезла
  за таймаут foreground-вызова и уронила живой контейнер.
- Долгий холодный старт OpenClaw CLI (~15–23с на одноразовый контейнер) — задокументирован
  как известное ограничение в `--help`, НЕ выдуман фикс через env-переменные (гипотеза
  проверена и опровергнута повторным тестом). Архитектурная альтернатива (persistent
  helper вместо `docker compose run --rm` на каждый вызов) сознательно не тронута —
  требует согласования с пользователем, выходит за рамки usability-фикса.
- Живой `apps/openclaw/.env` (git-ignored, не файл репозитория) обновлён напрямую на диске
  ради актуальных комментариев — значения (токен, порт, пути) не тронуты, коммита нет и
  не может быть (файл вне git).
