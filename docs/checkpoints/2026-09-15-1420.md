## Decisions

- Chose `#src/` / `#framework/` / `#checks/` / `#tools/` subpath imports over the user's literal
  `"@/"` request: Node's ESM resolver rejects any specifier starting with `#/`, and `@/` needs a
  bundler or loader this project deliberately does not have. Proven on one file before touching
  the other ~560 imports.
- Chose to rewrite `#src/...` specifiers into plain relative paths at build time (extending
  `build-framework-package.ts`'s existing `.ts`→`.js` rewrite) over shipping a `package.json`
  `imports` map in `dist/`: the published package stays as self-contained as it was before.
- Chose to fix `Transport.exists()` at the transport layer (all three implementations) over
  patching only the one caller the reviewer cited: the same conflation was latent in `restore`
  (which would skip moving live data aside) and `provider`.
- Chose to make `setAt()` throw on a `__proto__`/`constructor`/`prototype` segment and have
  `gatherInspection` catch it into a blocking CONFIG_DRIFT finding, over silently skipping the
  entry: a security-relevant input should not degrade quietly, but `inspect` must still answer.
- Chose to add `readLiveConfigOrThrow()` alongside the lenient `readLiveConfigForProspective()`
  rather than changing the latter: `inspect` genuinely needs the degrade-to-empty behaviour, and
  only the caller that WRITES from the result needs the strict one.
