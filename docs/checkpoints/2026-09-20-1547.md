## Decisions

- **Sequential `/rush`, never parallel, for #279–#282.** Not caution for its own sake: #279 and
  #280 both add entries to the same `ProblemCode` union and `PROBLEM_CODES` record in
  `tools/framework/service/inspection.ts`, and all four touch README plus the
  `openclawCommands.*.ts` help texts. This session already lost work once to exactly that kind of
  collision between two parallel runs.
- **Egress findings must be advisory, never blocking.** `doctor` exits non-zero on blocking
  findings, so a transient DNS blip would otherwise fail somebody's automation for a condition
  the deployment does not control.
- **#278 was done in-context, not delegated** — small, single-file, and the standing rule is that
  sub-agents need an explicit request.
- **#277 closed unimplemented.** Even after two rounds of ad-hoc host diagnostics this session,
  each investigation needed something different (bind test, DNS probe, port-owner lookup); a
  canned topology snapshot would have saved almost nothing.
- **Every task in this group carries tests + README + help in its definition of done**, with the
  concrete precedent recorded in the task text: #152 found `accept`'s help still promising
  "reported as skipped" long after the emitted value had become `not-checked`.
