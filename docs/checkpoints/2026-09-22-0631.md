- **Sequential `/wrush`, one worktree per task, never parallel when two tasks touch the same
  `ProblemCode` union or the same help/README regions.** Where two tasks' worktrees legitimately
  ran concurrently (disjoint file sets), every prompt named the sibling session and its scope
  explicitly.

  follow-up-task deferral. Concrete precedent cited in every prompt: `accept`'s help once
  promised "reported as skipped" long after the emitted value became `not-checked`.
- **Zero-trust means MY OWN mutation, not just re-reading the sub-agent's.** In `#279`, `#282`,
  and `#283` my independently-chosen mutation exposed a real gap the sub-agent's own
  break-and-restore had not covered; each was closed by a second `/rush` round scoped to only
  that gap, no behaviour change.

  restarted from scratch.** Happened twice (once for `#280`, once earlier for egress); both
  times the sub-agent's own prior diff was reviewed and built upon, not discarded.

  the finishing task's own hunks, verified by grepping for every earlier layer's marker text
  before and after — `cp` was never used when a worktree's README base predated a sibling's
  merge.
- **Never commit or push without an explicit user request**, even after all eleven tasks landed
  clean with a green full gate. The tree currently sits at 48 dirty files on top of `51af372`.
