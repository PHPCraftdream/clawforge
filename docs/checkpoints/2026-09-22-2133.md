## Decisions

- Строго последовательный `/wrush`, не параллельно — находки раунда 2 гораздо сильнее
  пересекаются по файлам (archive.ts/verify.ts/recipe.ts/private-config.ts/backup.ts/
  restore.ts/runtime-docker.ts), чем находки батча 1.
- Порядок очереди задан явно в описании каждой задачи при декомпозиции (P1 сначала, затем
  P2 в порядке из раздела отчёта "Порядок доработки", P3 последней) — не по номеру находки.
- Каждый новый worktree синхронизировался со ВСЕМИ уже смерженными правками предыдущих
  задач очереди перед стартом суб-агента — критично, т.к. почти каждая задача продолжала
  работу предыдущей в тех же файлах.
- Zero-trust = моя собственная мутация ДРУГОЙ части, не просто перечитывание чужой; там,
  где природа бага — "тихий skip", а не "падение теста" (P2-06), применена адаптация:
  верификация выполнением (симуляция отсутствия транспорта) вместо классического
  ломаю-код/тест-падает паттерна.
- Никогда не коммитить/пушить без явного запроса — дерево на 67 грязных файлах поверх
  `620ce8d`, не тронуто.
- Rush-лимит: не ретраить в известный отказ, сообщить пользователю и ждать явного решения
  (не выбирать fallback-агента самостоятельно) — сессия возобновлена в ту же `--session`
  после подтверждения пользователем сброса лимита, без потери частичного прогресса.
