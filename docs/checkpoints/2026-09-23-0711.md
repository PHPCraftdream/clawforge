Закрытые находки:
- **P1-01** (`#300`) — internal symlink внутри рецепта мог обойти privacy-классификацию
  (alias на приватный файл/каталог того же рецепта не проверялся повторно по разрешённому
  пути); двойная проверка (логический путь + realpath) в `collectPortableRecipeFiles()`,
  канонический контекст для directory-alias, защита от циклов.
- **P1-03** (`#301`) — deploy проверял только явные `privateFiles`, не общую sensitive-name
  policy (`.env.local`, `*.secrets.env` и т.п. проходили deploy, хотя import/build/mirror их
  держат приватными); deploy теперь сканирует `recipes/` и `config/` тем же
  `collectPortableRecipeFiles()`, что и остальные carriers.
- **P1-02** (`#302`) — история приватности (ledger) не путешествовала с backup — restore в
  новый operator-side каталог терял защиту; зеркальная копия ledger публикуется в data root
  при full backup (`config/clawforge-private-paths.json`), импортируется обратно при restore
  до любых действий, исключена из migrate/share.
- **P1-04** (`#303`) — restore проверял layout БЕЗ тех прав, с которыми потом действовал
  (extraction/chmod могли идти через sudo, проверка — нет); `verifyRestoredLayout` теперь
  использует тот же `sudoFor`-префикс, `presenceOf()` различает "отсутствует" от "нет прав
  проверить" (fail-closed на любом неожиданном exit-коде `test`).
- **P2-01** (`#304`) — одна приватная запись расширяла ВЕСЬ ancestor-каталог в исключение
  (запись в `config/secret.env` делала весь `config/` приватным); ledger теперь хранит пару
  (точный путь, исходная объявленная граница), а не все ancestors.
- **P2-02** (`#305`) — конкурентные private write в одном hook могли терять записи ledger
  (read-merge-write без сериализации); process-local promise-очередь мутаций, keyed по
  ledger-файлу (`mutatePrivatePathsLedger`).
- **P2-03** (`#306`) — составной apply автоматически перезаписывал намеренную правку
  оператора в `.env` значениями из контейнера; recover-env для ENV_STALE стал advisory
  (не executable step), явный `--adopt-runtime` для выбора направления синхронизации.
- **P2-04** (`#307`) — MCP-сессия (долгоживущий процесс) продолжала исполнять старую версию
  recipe hooks после правки файла на диске (Node import-кэш по URL); hook-модули теперь
  кэшируются по checksum содержимого, ре-импорт под query-параметром при изменении.
- **P2-05** (`#308`) — успешные MCP-ответы (включая gate-команды) обходили redaction —
  маскирование жило только на error-пути; теперь маскируется и success-путь (text +
  structured, ключи и значения), кроме явно объявленного `exportsSecrets: true` (mcp-creds).
- **P2-06** (`#309`) — egress-проверка не имела общего дедлайна (DNS вне таймера, HTTP body
  не отменялось, exec без timeoutMs); единый бюджет от dns.lookup, явная отмена body,
  timeoutMs протянут до exec с SIGTERM→SIGKILL эскалацией (5с grace).
