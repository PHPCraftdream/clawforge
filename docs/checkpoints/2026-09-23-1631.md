## Decisions

- Раунд 6 декомпозирован на 18 задач вместо 1:1 с 24 находками — кластеризация по
  пересечению файлов, чтобы минимизировать конфликты мержа (сработавший паттерн из round 4).
- Каждый новый worktree синхронизируется вручную (`cp` по `git status --porcelain`) поверх
  `git worktree add ... HEAD`, поскольку round-4 diff (а затем и накопленный round-6 diff)
  остаётся некоммиченным всю дорогу — иначе агенты не видели бы код находок.
- При обнаружении layout-лимита (700 строк / 7 файлов) — реструктуризация в поддиректорию
  (`file.ts` → `dir/{index.ts, ...}`) вместо произвольного relocation, с полным
  пересчётом внешних import-путей и повторной верификацией; тот же паттерн применён дважды
  (`deploy.ts`, `recipe.ts`) за сегмент.
- Rate-limit/timeout на агенте — транзитная ошибка, не повод для fallback: возобновление в
  ту же `rush --session` с увеличенным лимитом, без эскалации пользователю (согласно
  стандартной инструкции rush.md).
- Найденный класс инфраструктурных багов (lock-фикстуры, несовместимые с новым CAS-протоколом)
  чинился каждый раз немедленно при обнаружении, даже когда поломанный файл не входил в
  формальный scope текущей проверяемой находки — по стандартному правилу "флейк/падение
  чинится на месте".
