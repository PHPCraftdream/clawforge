# Backlog: P3 findings (class G and accepted limits)

Collected during the stage 6 review of [the refactoring plan](refactor-plan-2026-10-01.md). These are
handled in batches, not in review rounds. A finding of class A–F is never parked here: it is fixed.

| Item | Where | Why it is parked |
| --- | --- | --- |
| A bare program's double-quoted words are not POSIX-safe for `$` and backtick | `core/io/invocation/render.ts` (bare-program branch) | One quoting rule has to serve cmd, PowerShell and POSIX; single quotes break cmd. No advice word needs the characters today, and `advice-matrix.check.ts` fails if one ever does. |
| A `%` in an advice word pasted under the bare program is expanded by cmd.exe even inside double quotes | `core/io/invocation/render.ts` (SAFE_WORD) | No shell-agnostic safe spelling exists inside quotes; `%` stays in SAFE_WORD because POSIX and PowerShell treat it literally. Deployment names cannot contain `%` (safeName) and `advice-matrix.check.ts` refuses any advice word that carries one. |
| `set/load.ts` and `set/artifacts/*` import types and helpers from `commands/` | `tools/framework/set/` | Layering inversion, no behaviour defect. Moving `lock`, `accept` and `provision-agent` types to a lower layer touches many files. |
| Lazy `loadChecks` import in the check runner | `tools/checks/kit/` | Works; only the import style differs from the rest. |
| `digestOf` is lexical and lenient on purpose | `runtime/docker/image-ref.ts` | A pin recorded in a non-canonical spelling must keep comparing equal to itself; only `parse()` enforces the grammar. |
| The legacy `CLAWFORGE_INVOKED_AS` variable is still written by `init` and the shim | `integration/deployment/*` | Kept so older pinned frameworks keep spelling hints right; it is parsed in one place only. |
| `docs/guide/requirements.md` capability prose | docs | Narrative lists were updated once by hand; a generated table would remove the duplication. |
| A local-package hint pasted from a subdirectory of the deployment names a path that does not resolve there | `entry/root.ts` (defaultInvocation), `integration/deployment/init.ts` (shim) | Documented contract: hints are spelled relative to the deployment root. The committed shim exports `CLAWFORGE_INVOCATION` with program `./clawforge` unconditionally — even when the shim itself is invoked from a subfolder — init tells the operator to commit `./clawforge` at the root, the guide always invokes it there, and cron lines are built as `cd <deployment dir> && ./clawforge`. The subfolder walk in `entry/resolve.ts` serves the checkout gate and `--project-root` hand-over, not subfolder hint spelling (review R6-4). |
| `Invocation.audience` and `Invocation.mode` are written, serialized and strictly parsed but read by no surface | `core/io/invocation/index.ts`, `integration/mcp/project.ts` | Reserved: the launcher records the audience so a surface can render MCP-only advice (e.g. a shell-only hint as a manual step) without re-deriving the entry. The fields stay — versioned JSON, committed launchers write them, and the strict parser rejects unknown fields. |
| The legacy `AppCommand` adapter path parses argv inside `run`, after the context exists | `core/command/execute.ts` (adapter branch) | The adapter is the compatibility contract for deployment-authored commands (plan section 6): `arguments` of a legacy command describe it for help and MCP, but the command's own `run` may consume flags the declaration does not list (a pass-through command declaring only a variadic). A strict pre-parse refused such commands. The invariant (an argument error before any contact) holds for every declared body; the property check covers those. |
| `./clawforge` outside `tools/framework` (root shim comment, `docs/guide/*.md`, `.github/workflows/ci.yml`) is read by no program-name ratchet | `tools/checks/architecture/architecture.check.ts` | Every occurrence is the correct checkout spelling (the committed shim at the repository root); the ratchets guard text the framework prints, which lives under `tools/framework`. Widening them would need a reason-per-line table for pages that quote the shim by design. |
| `GateCommand` has no `rules` field and `refuseAgainstDeclaration` never calls `enforceRules` | `integration/gate.ts` | No gate command declares cross-field rules today. A gate command that did would have them ignored on the console and on MCP: add the field and the enforcement together with the first such command, and extend the property check's gate section. |
| `check --jobs -h` prints help instead of treating `-h` as the value of `--jobs` | `integration/gate.ts` (requestsHelp) | Deliberate: `-h`/`--help` before a bare `--` wins over any value-option binding, so help is always reachable (review R9-B). A command that wants a literal `-h` as a value takes it after a bare `--` or with the option spelled out. |
| The MCP surface drops an explicit `""` for an option while the console refuses `--opt=` | `integration/mcp/call.ts` (toArgv), `core/command/parse.ts` | Deliberate leniency (review R9-B): MCP clients send `""` for unset optional fields, so `toArgv` skips empty strings; the console keeps its strict inline-value grammar. Documented in the pipeline property check. |
| The prose ratchets (`PROSE_PIN`, `PROSE_MATCHER`) are blind to string literals that contain a backtick or a double quote (about 39 live pins, e.g. `spec/view.check.ts`, `security/expose/tailscale.check.ts`, `integration/apps/invocation-hints.check.ts`) | `tools/checks/architecture/architecture.check.ts` | Counting them needs a real tokenizer for template and escaped literals; a regex widened to cover them double counts neighbours. The pins stay visible in review, so the ratchet undercounts rather than misleads. |
| `check:exclusive` fixtures write into the real checkout (`apps/gateprobe-*`, `apps/golden-fixture`, `apps/sys-install-check-*`, `docs/<name>-empty`) and clean up only in `finally` | `tools/checks/**` (exclusive checks) | A killed run can leave a fixture behind. Moving them under the OS temp directory needs each fixture's resolver (`monorepoRoot`-relative lookups) to accept a root override first. |
| A malformed `agent/config.json` in a working tree leaves the recipe's agent undeclared in the manifest `set validate` collects, so acceptance checks naming that agent also report `SET_REFERENCE_BROKEN` next to the root `SET_RECIPE_INVALID` | `set/load.ts` (collectManifest, report mode) | The tree cannot derive a declaration from bytes that do not parse; the artifact path keeps the manifest's own declaration and reports one finding. Both name the file and recipe; suppressing the dependent finding needs the validator to know which declarations were unreadable. |
| `ArgumentRule.reason` is a plain string, so a rule whose reason names a command line must spell it through a getter (`rollback`'s `--previous-set` conflict) | `core/command/spec.ts`, `commands/orchestration/rollback.ts` | The invocation is set after import. A first-class lazy reason (thunk or prose token rendered in `ruleText`) belongs in `core/command`, outside this batch's scope; the new top-level-advice check keeps the import-time pattern from coming back. |
| The top-level-advice guard is a lexical scan (strings, comments, regex literals, template placeholders, brace and arrow tracking), not an AST walk | `tools/checks/surfaces/top-level-advice.check.ts` | The toolchain ships no parser API; the scanner is pinned by fixtures for each shape the product uses. A helper that renders advice indirectly at import time (a module-level call to a function that calls `commandLine`) is not seen. |
| `AppCommand.readOnlyWhen`, `changedWhen` and `requiresConfirmationWhen` still read raw argv | `core/app.ts`, `core/command/effect.ts`, `integration/mcp/call.ts` | Legacy-adapter contract: a deployment-authored `AppCommand` may declare them, and the adapter keeps honouring them (plan section 6). No shipped command declares one (`rawArgvPredicates` is 0 in the ratchet baseline); spec bodies derive the same facts from the declaration. Removing the hooks would break such commands, so they stay until the adapter itself is retired. |
