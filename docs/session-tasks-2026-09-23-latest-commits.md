# Сессионные задачи по последним коммитам

Проверено состояние `main` на `12f1704`. Задачи раунда 7 `#341–#351` уже перечислены в
`docs/checkpoints/2026-09-23-2320.md` и здесь не дублируются. Ниже — новые задачи,

## Статус задач

### LC-01 [P1, завершено] Проверить и очистить опубликованные checkpoints

**Основание:** `12f1704` убрал `docs/checkpoints/` из `.gitignore` и добавил накопленные
сессионные записи. Поиск обнаруживает локальные пути как минимум в четырёх отслеживаемых
файлах. Сами пути и значения секретов в этот список не копируются.

**Готово, когда:** все отслеживаемые checkpoints проверены на частные пути и значения;
публичное дерево очищено; отдельно принято решение, требуется ли исправление уже
опубликованной истории Git. Проверить, что задача не удаляет полезные сведения о ходе работ.

**Результат:** все Markdown-файлы `docs/` проверяются на частные пути и значения.
История `main` переписана с согласия пользователя: checkpoint-файлы и отчёт CI
появляются в ней сразу в очищенном виде. Дерево `f750e06` совпадает с деревом
предыдущего зелёного коммита, полезные сведения сохранены.

### LC-02 [P1, завершено] Найти причину пустых checksum-результатов на Windows CI

**Основание:** `b10aa0c` документирует четыре падающие проверки в
`tools/checks/runtime/convergence/inspect/checksums.check.ts`. В CI для `12f1704`
Linux job успешен, Windows job падает на Windows-capable subset.

**Готово, когда:** на hosted Windows runner определены фактический `sh`, аргумент каталога,
код выхода и stderr вызова без вывода приватных путей; исправлена подтверждённая причина;
все четыре проверки проходят, а проверки отсутствия shell-инъекции сохранены.

**Результат:** hosted runner возвращал бинарный маркер `*` в выводе `sha256sum`; прежний
парсер отбрасывал все строки. Исправлены оба штатных формата и явная обработка ошибок
shell. Проверки прошли в финальном CI; подробности — в
`docs/ci-windows-inspect-checksums-gap-2026-09-23.md`.

### LC-03 [P2, завершено] Добавить защиту при публикации checkpoint-файлов

**Основание:** `12f1704` сделал checkpoints частью истории, хотя прежнее правило исключало
их из-за машинных данных. Новый файл должен проходить проверку до коммита.

**Готово, когда:** репозиторная проверка выявляет частные абсолютные пути и непустые
credential-поля в `docs/checkpoints/`, не печатая найденные значения; для безопасных
относительных ссылок и синтетических примеров есть явные исключения. Зависит от `LC-01`.

**Прогресс:** `docs-private-content.check.ts` проверяет Markdown-файлы `docs/` и сообщает
только относительный файл, строку и тип находки. Проверка добавлена в Windows CI subset.

### LC-04 [P2, завершено] Закрепить cross-drive исправление `set try` регрессией

**Основание:** `948445a` заменил относительный import на file URL, потому что временный
каталог и checkout на Windows могут быть на разных дисках. В существующих set-try checks
нет отдельного утверждения именно для этого случая.

**Готово, когда:** Windows-проверка создаёт app import при разных корнях дисков и
подтверждает загрузку модуля; она включена в Windows CI и не зависит от случайной
раскладки дисков конкретного runner.

**Прогресс:** добавлена явная проверка `file://` импорта между разными корнями дисков;
целевой Windows check прошёл локально.

### LC-05 [P2, завершено] Подтвердить полный CI после исправлений

**Основание:** после серии `14ae12b`–`948445a` Linux job стал зелёным, но последний
полный run на `12f1704` остаётся красным из-за Windows subset. Локальные прогоны не
заменяют эту проверку.

**Готово, когда:** один run на итоговом commit завершён успешно в Linux и Windows jobs,
включая тесты, typecheck/lint, build и pack; ссылки на run и commit записаны рядом с
результатом. Зависит от `LC-02`; после `LC-03` и `LC-04` запуск повторяется при их изменениях.

**Результат:** [CI run 35935302856](https://github.com/PHPCraftdream/clawforge/actions/runs/35935302856)
на `85f1360` завершился успешно в Linux и Windows jobs, включая checks,
typecheck/lint, build и pack. Локально также прошли 106 check-файлов и actionlint.
